三、新浪财经：分时走势

请求

GET https://stock2.finance.sina.com.cn/futures/api/jsonp.php/var%20t=/InnerFuturesNewService.getMinLine?symbol=SA2701
  • 返回 JSONP，需剥离 var t=(...) 外壳
  • 单次返回当日全部分时点

响应结构

[
  { "date": "2026-10-09", "time": "21:00:00", "price": "1007", "average": "1008",
    "volume": "44239", "position": "1185430" },
  ...
]
字段含义
date日期
time时:分:秒
price该分钟最新价
average当日均价（VWAP）
volume该分钟成交量
position持仓量

交易时段自动还原

本项目不硬编码任何交易时段。后端用 1 分钟 K 线还原该合约的完整分钟序列，

从而自动得出该品种的交易时段格子数。例如：

  • 纯碱（SA）= 夜盘 21:00-22:59 + 日盘 09:00-14:59 = 345 格
  • 中金所股指 = 无夜盘，日盘时段也不同

换任何品种都自动适配，横轴按整段交易时段摊满全宽。

周 / 月 / 年 K 由日 K 合成

上游没有周月年 K 接口，本项目在前端由日 K 合成：

开盘价 = 该周期第一根日K的开盘价
最高价 = 该周期内最高价的最大值
最低价 = 该周期内最低价的最小值
收盘价 = 该周期最后一根日K的收盘价
成交量 = 该周期内成交量求和
持仓量 = 该周期最后一根日K的持仓量（期末值）

字段说明

⚠️ NaN 陷阱（本项目真实生产事故）

非交易时段天勤会把 bid_price1 / ask_price1 等返回为 nan。

Python 的 json.dumps 默认会把 nan 写成裸 NaN——这是非法 JSON，

浏览器 res.json() 会直接抛 Unexpected token 'N'，导致「天勤」档整档失效。

本项目做了双保险修复：

  1. 源头收敛：fnum() / inum() 把 nan / ±Infinity 统一转为 0；
  2. 响应层兜底：json.dumps(..., allow_nan=False)，失败则走 _json_safe() 递归把非法浮点降级为 null。

七、加权指数算法

为什么需要自己合成

新浪没有真正的加权指数（SA99 / SA888 之类的代码实测返回空）。

而加权指数比主力连续更能反映整个品种的真实价格水平，所以本项目本地合成。

快照（实时行情）算法

指数最新价 = Σ(合约最新价 × 合约权重) / Σ(合约权重)
指数昨结   = Σ(合约昨结价 × 合约权重) / Σ(合约权重)   → 涨跌口径与单合约一致
指数开/高/低 = 各字段同权重加权
指数成交量/持仓量 = Σ(各合约)
  • 权重 = 各合约的持仓量（weight=oi，默认）或成交量（weight=vol）
  • 主力连续 XX0 不参与（它只是主力月份的影子，纳入会重复计权）
  • 权重明细随接口返回（components 字段），可核查
  • 性能：快照只取覆盖 97% 权重的前 N 个合约（3~8 个）

分时算法

各成分合约的分时点按时间戳对齐后加权：

  1. 取所有成分合约时间戳的并集；
  2. 每个合约在缺失的时刻用前收盘价前向填充（尚未开盘的时刻为 None，不参与加权）；
  3. 逐时刻按该时刻的持仓量加权。

K 线算法：日 K 与分钟线用两套口径

这是本项目最容易出错的算法点。历史日 K 必须逐根动态加权：

分钟线（1/5/…/120 分）日 K（历史长序列）
成分合约当刻持仓量 Top-N（3~8 个）枚举历史上出现过的全部月份合约
权重当刻持仓量，固定不变每根 K 线自身的持仓量（逐 bar 变化）
理由分钟线只覆盖当日，主力月份不会变主力月份会随时间轮换，用今天的名单加权历史会严重漏算

实测教训（曾低估 200 倍）

曾用「今天的 Top-N + 固定权重」合成历史日 K，结果：

日期合成成交量主力连续成交量偏差
2026-03-165,452 手1,156,521 手低估约 200 倍

原因：当天真正的近月合约是 SA2605（成交 115 万手），但它不在今天的成分名单里。

改为「全合约枚举 + 逐 bar 动态持仓量加权」后，成交量与主力连续量级一致。

两个配套细节

① 合约枚举深度：all_contract_codes(product, years_back=7)

必须回溯 7 年才能覆盖新浪日 K 的实际历史。默认只回溯 3 年时会漏掉

2019 / 2022 年的当月合约（如 CU2204 当日成交 6.9 万手），成交量被低估数百倍。

品种加权日 K 根数起始日期
RBW 螺纹2,0142018-06-19
CUW 铜2,0142018-06-19
MW 豆粕1,9952018-07-16
AUW 黄金1,9722018-08-16
IFW 沪深3001,8692019-01-21
SAW 纯碱1,6562019-12-06

② 真实覆盖率门限：MIN_REAL_COVER = 0.9

固定权重模式下，若某根 K 线的「有真实行情成分权重 / 全体成分权重」低于 0.9，

则丢弃该根，避免合约刚上市、多数成分无数据时算出脏值。

注意分母是全体成分权重而不是「当刻可用权重」。

早期版本用了后者（在可用成分内重新归一化），导致只有 1 个成分也能通过门限，

算出过 1371 的脏值（真实约 1010）。

九、缓存策略

内部使用 TTL 缓存，避免频繁打上游：

数据TTL
实时行情交易时段 2~15 秒
分时 / K 线数秒
品种表较长（中文名变动不频繁）
加权指数独立缓存（wquote: / wts: / wk:）
休市期间自动拉长

上游异常时自动回退上一次成功数据，保证界面不空白。

十、反爬与兼容处理

问题处理
需要 Referer 校验所有新浪请求统一带 Referer: https://finance.sina.com.cn
需要 User-Agent统一使用 Chrome UA

UTC/时区全部使用本地时间（Asia/Shanghai 语义），不做时区转换

十一、本项目自身的 HTTP 接口

服务默认监听 http://127.0.0.1:8686/。

路径说明
GET /前端面板页面
GET /api/quote?symbol=SA2701实时行情（支持主力连续 SA0、加权 SAW）
GET /api/products全品种树（79 品种 × 5 交易所，含中文名 / 停牌标记）

GET /api/quote?symbol=SAW
