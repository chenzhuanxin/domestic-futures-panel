## 二、新浪财经：实时行情

### 请求

```http
GET https://hq.sinajs.cn/list=nf_SA2701
Referer: https://finance.sina.com.cn
```

- 代码格式：`nf_` + 合约代码
- **支持批量**：多个代码用英文逗号连接，一次最多约 100 个
  ```http
  GET https://hq.sinajs.cn/list=nf_SA2701,nf_SA2705,nf_SA0
  ```
  本项目按 **40 个一批** 分组请求。

> ⚠️ **必须带 `Referer`**，否则新浪会返回空内容。

### 响应

```
var hq_str_nf_SA2701="纯碱2701,1010.000,1011.000,995.000,1001.000,...,2026-10-09,23:00:00,1";
```

### 商品期货字段布局（44 字段）

适用于**郑商所 / 大商所 / 上期所 / 广期所**。下表为本项目实际使用的下标：

| 下标 | 字段 | 项目内名称 | 说明 |
|---|---|---|---|
| `f[0]` | 名称 | `name` | 如 `纯碱2701` |
| `f[2]` | 开盘价 | `open` | 含夜盘 |
| `f[3]` | 最高价 | `high` | |
| `f[4]` | 最低价 | `low` | |
| `f[6]` | 买一价 | `bid` | |
| `f[7]` | 卖一价 | `ask` | |
| `f[8]` | 最新价 | `last` | |
| `f[9]` | 昨收盘 | `preclose` | **分时图基准线**用这个 |
| `f[10]` | 昨结算 | `presettle` | **涨跌幅基准**用这个 |
| `f[13]` | 持仓量 | `oi` | 单位：手 |
| `f[14]` | 成交量 | `volume` | 单位：手 |
| `f[15]` | 交易所代码 | `exchange` | 需映射为中文名 |

### 中金所字段布局（50 字段）

适用于**股指期货 / 国债期货**（中金所）。结构与商品期货**完全不同**，
`f[0]` 直接是价格，**没有名称字段**：

| 下标 | 字段 | 项目内名称 |
|---|---|---|
| `f[0]` | 开盘价 | `open` |
| `f[1]` | 最高价 | `high` |
| `f[2]` | 最低价 | `low` |
| `f[3]` | 最新价 | `last` |
| `f[4]` | 成交量 | `volume` |
| `f[5]` | 成交额 | （未使用） |
| `f[6]` | 持仓量 | `oi` |
| `f[9]` | 结算价 | `settle`（**盘中常为无效值**） |
| `f[10]` | 昨结算 | `presettle` |
| `f[11]` / `f[12]` | 买量 / 卖量 | `bidvol` / `askvol` |
| `f[13]` / `f[14]` | 买价 / 卖价 | `bid` / `ask` |

### 中金所的两个特殊处理

1. **名称缺失**：中金所行情不带名称，项目用「品种中文名 + 主力」兜底（如「沪深300主力」）。
2. **买卖盘与量仓可能全为 0**：项目会用**同品种成交量最大的月份合约**快照
   回填空缺字段（**只补空缺，不覆盖自身有效值**），并据此重算涨跌。

## 三、新浪财经：分时走势

### 请求

```http
GET https://stock2.finance.sina.com.cn/futures/api/jsonp.php/var%20t=/InnerFuturesNewService.getMinLine?symbol=SA2701
```

- 返回 **JSONP**，需剥离 `var t=(...)` 外壳
- 单次返回**当日全部分时点**

### 响应结构

```json
[
  { "date": "2026-10-09", "time": "21:00:00", "price": "1007", "average": "1008",
    "volume": "44239", "position": "1185430" },
  ...
]
```

| 字段 | 含义 |
|---|---|
| `date` | 日期 |
| `time` | 时:分:秒 |
| `price` | 该分钟最新价 |
| `average` | 当日均价（VWAP） |
| `volume` | 该分钟成交量 |
| `position` | 持仓量 |

### 交易时段自动还原

**本项目不硬编码任何交易时段**。后端用 1 分钟 K 线还原该合约的完整分钟序列，
从而自动得出该品种的交易时段格子数。例如：

- 纯碱（SA）= 夜盘 `21:00-22:59` + 日盘 `09:00-14:59` = **345 格**
- 中金所股指 = 无夜盘，日盘时段也不同

换任何品种都自动适配，横轴按整段交易时段摊满全宽。

## 五、新浪财经：日 K 线

### 请求

```http
GET https://stock2.finance.sina.com.cn/futures/api/jsonp.php/var%20t=/InnerFuturesNewService.getDailyKLine?symbol=SA2701
```

- 返回该合约**自上市以来**的完整日 K
- 实测可回溯约 **4~7 年**（铜 CU 可到 2018-06，纯碱 SA 可到 2019-12）

### 响应结构

与分钟 K 线同构：

```json
[
  { "d": "2026-10-09", "o": "1010", "h": "1011", "l": "995",
    "c": "1001", "v": "544401", "p": "1189921" },
  ...
]
```

| 字段 | 含义 |
|---|---|
| `d` | 交易日期 |
| `o` / `h` / `l` / `c` | 开 / 高 / 低 / 收 |
| `v` | 成交量（手） |
| `p` | 持仓量（手） |

### 周 / 月 / 年 K 由日 K 合成

上游没有周月年 K 接口，本项目在**前端**由日 K 合成：

```javascript
开盘价 = 该周期第一根日K的开盘价
最高价 = 该周期内最高价的最大值
最低价 = 该周期内最低价的最小值
收盘价 = 该周期最后一根日K的收盘价
成交量 = 该周期内成交量求和
持仓量 = 该周期最后一根日K的持仓量（期末值）
```

## 六、天勤（快期）官方指数与主连

**仅在使用「天勤」指数口径时需要**。官方文档：<https://www.shinnytech.com/>

### 认证

```python
import tqsdk

# ⚠️ 必须传 TqAuth 对象，传元组/裸字符串会静默变成 self._auth is None
auth = tqsdk.TqAuth("账号", "密码")
api = tqsdk.TqApi(auth=auth, web_gui=False, disable_print=True)
```

| 参数 | 作用 |
|---|---|
| `auth` | **必须**是 `TqAuth` 对象 |
| `web_gui=False` | 不启动本地 Web 面板 |
| `disable_print=True` | 抑制免责声明、账户信息等刷屏日志 |

> **预热技巧**：`TqApi` 构造后数据通道尚未就绪，直接查 `KQ.i` / `KQ.m` 会偶发超时。
> 先 `api.get_quote("SHFE.rb2601")` 订阅一个必然存在的合约，把通道带起来即可稳定。

### 代码格式

| 代码 | 含义 | 示例 |
|---|---|---|
| `KQ.i@<交易所>.<品种>` | **指数** | `KQ.i@CZCE.SA` |
| `KQ.m@<交易所>.<品种>` | **主连** | `KQ.m@CZCE.SA` |

### ⚠️ 交易所大小写（极易踩坑）

| 交易所 | 大小写 | 正确示例 |
|---|---|---|
| **CZCE**（郑商所） | **大写** | `CZCE.SA` |
| **CFFEX**（中金所） | **大写** | `CFFEX.IF` |
| SHFE（上期所） | 小写 | `SHFE.rb` |
| DCE（大商所） | 小写 | `DCE.m` |
| GFEX（广期所） | 小写 | `GFEX.lc` |
| INE（上海国际能源） | 小写 | `INE.sc` |

写错会报 `non-existent instrument`。

### 返回类型不一致（坑）

| 代码类型 | 返回类型 | 取值方式 |
|---|---|---|
| `KQ.m`（主连） | `Quote` | `getattr` 或 `[]` 均可 |
| `KQ.i`（指数） | `D`（**dict 子类**） | **`getattr` 无效**，必须用 `s["字段名"]` |

本项目统一用 `s[字段名]` 取值以兼容两种类型。

### 字段名

| 字段 | 说明 |
|---|---|
| `last_price` | 最新价 |
| `open` / `highest` / `lowest` | **开 / 高 / 低**（注意**没有** `open_price`） |
| `pre_settlement` | 昨结算 |
| `pre_close` | 昨收盘 |
| `volume` | 成交量 |
| `open_interest` | 持仓量 |
| `bid_price1` / `ask_price1` | 买一 / 卖一 |

### ⚠️ NaN 陷阱（本项目真实生产事故）

**非交易时段**天勤会把 `bid_price1` / `ask_price1` 等返回为 `nan`。
Python 的 `json.dumps` 默认会把 `nan` 写成**裸 `NaN`**——这是**非法 JSON**，
浏览器 `res.json()` 会直接抛 `Unexpected token 'N'`，导致「天勤」档**整档失效**。

本项目做了**双保险**修复：

1. **源头收敛**：`fnum()` / `inum()` 把 `nan` / `±Infinity` 统一转为 `0`；
2. **响应层兜底**：`json.dumps(..., allow_nan=False)`，失败则走 `_json_safe()` 递归把非法浮点降级为 `null`。

### 交叉验证结果

本地持仓量加权指数 vs 天勤官方 `KQ.i`（同一次采样）：

| 品种 | 本地加权 | 天勤官方 | 偏差 |
|---|---|---|---|
| SA 纯碱 | 1008.87 | 1009.0 | +0.013% |
| RB 螺纹钢 | 3096.69 | 3097.0 | +0.010% |
| M 豆粕 | 3311.87 | 3312.0 | +0.004% |
| IF 沪深300 | 4243.59 | 4243.3 | −0.007% |
| LC 碳酸锂 | 116501.76 | 116549.0 | +0.041% |
| CU 铜 | 110069.64 | 110072.0 | +0.002% |

**5 家交易所 6 个品种偏差全部 ≤ 0.041%**，证明本地加权算法可信。

## 七、加权指数算法

### 为什么需要自己合成

新浪**没有真正的加权指数**（`SA99` / `SA888` 之类的代码实测返回空）。
而加权指数比主力连续更能反映整个品种的真实价格水平，所以本项目本地合成。

### 快照（实时行情）算法

```
指数最新价 = Σ(合约最新价 × 合约权重) / Σ(合约权重)
指数昨结   = Σ(合约昨结价 × 合约权重) / Σ(合约权重)   → 涨跌口径与单合约一致
指数开/高/低 = 各字段同权重加权
指数成交量/持仓量 = Σ(各合约)
```

- **权重 = 各合约的持仓量**（`weight=oi`，默认）或**成交量**（`weight=vol`）
- **主力连续 XX0 不参与**（它只是主力月份的影子，纳入会重复计权）
- 权重明细随接口返回（`components` 字段），可核查
- 性能：快照只取覆盖 97% 权重的前 N 个合约（3~8 个）

### 分时算法

各成分合约的分时点按**时间戳对齐**后加权：

1. 取所有成分合约时间戳的**并集**；
2. 每个合约在缺失的时刻**用前收盘价前向填充**（尚未开盘的时刻为 `None`，不参与加权）；
3. 逐时刻按该时刻的持仓量加权。

### K 线算法：日 K 与分钟线用**两套**口径

这是本项目最容易出错的算法点。**历史日 K 必须逐根动态加权**：

| | 分钟线（1/5/…/120 分） | 日 K（历史长序列） |
|---|---|---|
| **成分合约** | 当刻持仓量 Top-N（3~8 个） | **枚举历史上出现过的全部月份合约** |
| **权重** | 当刻持仓量，**固定不变** | **每根 K 线自身的持仓量**（逐 bar 变化） |
| **理由** | 分钟线只覆盖当日，主力月份不会变 | 主力月份会随时间轮换，用今天的名单加权历史会**严重漏算** |

#### 实测教训（曾低估 200 倍）

曾用「今天的 Top-N + 固定权重」合成历史日 K，结果：

| 日期 | 合成成交量 | 主力连续成交量 | 偏差 |
|---|---|---|---|
| 2026-03-16 | 5,452 手 | 1,156,521 手 | **低估约 200 倍** |

原因：当天真正的近月合约是 **SA2605**（成交 115 万手），但它**不在今天的成分名单里**。
改为「全合约枚举 + 逐 bar 动态持仓量加权」后，成交量与主力连续量级一致。

#### 两个配套细节

**① 合约枚举深度：`all_contract_codes(product, years_back=7)`**

必须回溯 **7 年**才能覆盖新浪日 K 的实际历史。默认只回溯 3 年时会漏掉
2019 / 2022 年的当月合约（如 `CU2204` 当日成交 6.9 万手），成交量被低估数百倍。

| 品种 | 加权日 K 根数 | 起始日期 |
|---|---|---|
| RBW 螺纹 | 2,014 | 2018-06-19 |
| CUW 铜 | 2,014 | 2018-06-19 |
| MW 豆粕 | 1,995 | 2018-07-16 |
| AUW 黄金 | 1,972 | 2018-08-16 |
| IFW 沪深300 | 1,869 | 2019-01-21 |
| SAW 纯碱 | 1,656 | 2019-12-06 |

**② 真实覆盖率门限：`MIN_REAL_COVER = 0.9`**

固定权重模式下，若某根 K 线的「**有真实行情**成分权重 / **全体**成分权重」低于 0.9，
则**丢弃该根**，避免合约刚上市、多数成分无数据时算出脏值。

> 注意分母是**全体成分权重**而不是「当刻可用权重」。
> 早期版本用了后者（在可用成分内重新归一化），导致只有 1 个成分也能通过门限，
> 算出过 1371 的脏值（真实约 1010）。

## 八、字段口径对照

### 涨跌基准

| 用途 | 基准 | 原因 |
|---|---|---|
| **头部涨跌 / 涨跌幅** | **昨结算价** | 与交易所、主流期货软件一致（期货按结算价做每日盈亏） |
| **分时图基准线** | **昨收盘价** | 与新浪分时图口径一致 |

两者口径不同是**刻意为之**，不是 bug。

### 量仓口径

| 字段 | 口径 |
|---|---|
| 成交量 | **双边**（买卖各计一次），单位：手 |
| 持仓量 | **双边**，单位：手 |

与新浪财经网页、交易所公布口径一致。

## 九、缓存策略

内部使用 TTL 缓存，避免频繁打上游：

| 数据 | TTL |
|---|---|
| 实时行情 | 交易时段 **2~15 秒** |
| 分时 / K 线 | 数秒 |
| 品种表 | 较长（中文名变动不频繁） |
| 加权指数 | 独立缓存（`wquote:` / `wts:` / `wk:`） |
| 休市期间 | **自动拉长** |

**上游异常时自动回退上一次成功数据**，保证界面不空白。

## 十、反爬与兼容处理

| 问题 | 处理 |
|---|---|
| 需要 `Referer` 校验 | 所有新浪请求统一带 `Referer: https://finance.sina.com.cn` |
| 需要 `User-Agent` | 统一使用 Chrome UA |
| 本机系统代理干扰（502） | 用 `ProxyHandler({})` **绕过代理直连** |
| JSONP 外壳 | 统一 `parse_jsonp()` 剥离 `var t=(...)` |
| 中金所无名称 / 无买卖盘 | 用同品种成交量最大的月份合约回填空缺字段 |
| 已停牌品种仍返回最后一次报价 | 用**主力日 K 的最后日期**判断（>10 天无交易视为停牌，置灰） |
| 天勤 NaN 污染 JSON | 源头 `fnum`/`inum` 收敛 + 响应层 `allow_nan=False` |
| UTC/时区 | 全部使用本地时间（`Asia/Shanghai` 语义），不做时区转换 |

| 路径 | 说明 |
|---|---|
| `GET /` | 前端面板页面 |
| `GET /api/quote?symbol=SA2701` | 实时行情（支持主力连续 `SA0`、加权 `SAW`） |
| `GET /api/products` | 全品种树（79 品种 × 5 交易所，含中文名 / 停牌标记） |
| `GET /api/symbols?product=SA` | 同品种合约列表（加权指数置顶 + 主连 + 全部月份） |
| `GET /api/symbols?product=SA&weight=vol` | 加权口径切换：`oi`（默认）/ `vol` / `tianqin` |
| `GET /api/timeshare?symbol=SA2701` | 分时数据（含完整交易时段 `slots`，供横轴自适应） |
| `GET /api/kline?symbol=SA2701&period=day` | K 线（`1/5/15/30/60/120/day`） |
| `GET /api/tq/status` | 天勤（快期）连接状态 |
| `GET /api/health` | 健康检查 |

**加权指数**只需把 `symbol` 换成 `XXW`（如 `SAW`）：

```http
GET /api/quote?symbol=SAW
GET /api/timeshare?symbol=SAW
GET /api/kline?symbol=SAW&period=day
```

**统一响应结构**：

```json
{ "ok": true, "ts": 1791562297278, "data": { ... } }
```

失败时 `ok=false` 并带 `error` 字段。
